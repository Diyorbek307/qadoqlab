# QADOQLAB — сайт производства картонных коробок

Двуязычный (RU / UZ) B2B-сайт, задача которого — получить от посетителя качественный запрос на расчёт упаковки.
Статические страницы собираются генератором на Node.js без внешних зависимостей; небольшой сервер на Node.js отдаёт сайт и принимает заявки.

```
npm run build        # публичная сборка → dist/ (только подтверждённый контент)
npm run build:demo   # демо-сборка → dist-demo/ (все категории с пометкой «Демо», noindex)
npm start            # сервер: сайт + /api/status + /api/request + /admin/ (порт 8080)
npm run admin:password  # хеш пароля для админ-панели
npm test             # 32 проверки приёма заявок и безопасности сервера + 22 проверки админ-панели
npm run test:browser # 30 проверок в браузере (нужен Playwright с Chromium)
npm run check        # проверка сборки: ссылки, H1, alt, почта, формулировки, языки, секреты
npm run lint         # ESLint (запускается через npx, в проект не устанавливается)
npm run format       # Prettier
```

Требования: Node.js ≥ 18.17. `npm install` не нужен — зависимостей нет.
Playwright нужен только для `npm run render:static` (перерисовка favicon и OG-изображения), он не входит в сайт.

## Админ-панель

Адрес — `/admin/` на том же сервере. Панель предназначена для владельца сайта, без ролей и CRM.

| Раздел | Что можно сделать |
|---|---|
| Обзор | Состояние заявок, файлов, индексации, каталога, политики и аналитики; список «что осталось заполнить»; тестовое письмо; пересборка; счётчики доставленных заявок |
| Контакты и реквизиты | Email, телефон, Telegram, WhatsApp, адрес и время работы (RU/UZ), координаты; реквизиты оператора данных и публикация политики |
| Каталог | Подтверждение печати; публикация каждого вида упаковки (с подтверждением); тексты категорий на двух языках |
| Тексты сайта | Все тексты интерфейса RU и UZ рядом: поиск, фильтр по разделу, «только изменённые», возврат исходного текста |
| Фотографии | Загрузка реальных фото в галерею и раздел «О производстве», описание для незрячих на двух языках, отметка «иллюстрация», удаление |
| Домен и аналитика | Домен (включает индексацию), идентификаторы GA4 и Яндекс Метрики |

**Включение**
1. `npm run admin:password` — придумайте пароль не короче 12 символов; скрипт выведет строку `ADMIN_PASSWORD_HASH=…`. Сам пароль нигде не сохраняется.
2. Добавьте эту строку в переменные окружения сервера или в `.env`. По желанию — `ADMIN_SESSION_SECRET`: случайная строка, чтобы вход сохранялся после перезапуска.
3. Перезапустите сервер и откройте `/admin/`.

**Как сохраняются изменения.** Правки пишутся в `DATA_DIR` (по умолчанию `data/`) поверх исходных файлов, которые не меняются. Затем сайт собирается в соседнюю папку и подменяет текущую сборку; при ошибке сборки остаётся прежний сайт. Обычно это занимает 1–2 секунды. `DATA_DIR` должен лежать на постоянном диске хостинга, иначе правки пропадут при новом развёртывании.

**Защита**
- Без `ADMIN_PASSWORD_HASH` все адреса `/admin/` отвечают 404.
- Пароль хранится как хеш scrypt.
- Сессия — подписанный cookie (`HttpOnly`, `SameSite=Strict`, `Path=/admin`, `Secure` при HTTPS) на 8 часов; выход отзывает её.
- Не больше 5 неудачных попыток входа за 15 минут с одного IP.
- Изменения принимаются только со своего домена и только скриптом панели.
- Все поля проверяются на сервере: форматы, длины, обязательность, сохранность подстановок вида `{email}`.
- Тексты на сайте экранируются.
- Фото проверяются по содержимому (JPG, PNG, WebP, до 6 МБ и 6000 px) и сохраняются под именем-хешем.
- Панель закрыта от индексации: `X-Robots-Tag` и `Disallow: /admin/` в robots.txt.

**Заявки панель не хранит**: они приходят на почту. В обзоре — только количество доставленных писем и ошибок с момента запуска сервера.

## Управление контентом

Обычно — через админ-панель. Без панели: значения по умолчанию в `config/site.config.js` и `content/`, затем `npm run build`.

**Контакты.** Заполненное поле появляется в подвале и на странице контактов; пустое — скрыто целиком, без заглушек. Карта (ссылка на OpenStreetMap) показывается только при заполненных и адресе, и координатах.

**Каталог.** `catalogPublished['transport-boxes'] = true` публикует категорию: карточку, страницу, ссылку в sitemap. Пока все категории выключены, раздел «Варианты упаковки» показывает блок «Коробка под вашу продукцию» с перечнем данных для расчёта — без утверждений об ассортименте. Категория `printed-boxes` дополнительно требует `capabilities.printing = true`.

**Возможности** (`capabilities`) — печать, собственная доставка, пищевые материалы, приём образцов — выключены. Тексты сайта о них ничего не утверждают: печать, доставка и сроки «уточняются при расчёте».

**Галерея и фото производства** (`gallery`, `aboutPhotos`). Раздел появляется, только когда в нём есть реальные материалы. Положите изображение в `src/static/` или отдельную папку `media/`, укажите `src`, `width`, `height`, `alt` на двух языках. Для иллюстраций ставьте `illustration: true` — подпись «Иллюстрация упаковки» добавится автоматически. Не указывайте заказчиков, тиражи и результаты проектов без их согласия.

**Тексты** — в `content/i18n/*.js`. Ключи одинаковы для обоих языков; при добавлении текста добавляйте оба перевода.

## Подключение отправки заявок

Сервер отправляет письмо через HTTP API почтового сервиса. Реализован адаптер **Resend** (бесплатный тариф достаточен для заявок). Ключи хранятся только в переменных окружения сервера — в клиентском коде и репозитории их нет.

1. Зарегистрируйтесь на resend.com и подтвердите свой домен (DNS-записи SPF/DKIM). Отправлять от имени `@gmail.com` нельзя: Gmail-адрес не может быть подтверждённым отправителем стороннего сервиса.
2. Создайте API-ключ с правом отправки.
3. На сервере задайте переменные (образец — `.env.example`; файл `.env` в корне тоже читается):
   ```
   MAIL_PROVIDER=resend
   RESEND_API_KEY=re_…
   MAIL_FROM=QADOQLAB <requests@ваш-домен.uz>
   MAIL_TO=qadoqlab.uz@gmail.com
   ```
4. Перезапустите сервер. `GET /api/status` вернёт `{"online":true,…}`, и форма переключится с «Подготовить письмо» на «Отправить запрос на расчёт».
5. Отправьте тестовую заявку и проверьте письмо в qadoqlab.uz@gmail.com (и папку «Спам»).
6. Файлы: `UPLOADS_ENABLED=true`. Файлы проверяются на сервере по сигнатуре (не по расширению), переименовываются в `attachment-N.ext`, не сохраняются на диск и не публикуются — только прикладываются к письму.

Другой сервис (Brevo, Postmark, SMTP-шлюз с HTTP API) подключается новым адаптером в `server/mail.js` с теми же методами `isConfigured()` и `send()`.

**Как работает отправка**
- «Запрос отправлен» показывается только после ответа `200 {ok:true}`, который сервер даёт, когда почтовый сервис принял письмо.
- Ошибка → сообщение «Не удалось отправить запрос… напишите на qadoqlab.uz@gmail.com», все введённые данные остаются в форме.
- Если отправка не настроена → `503 not_configured`; форма работает в режиме письма из почтового приложения.
- Защита: проверка и нормализация всех полей на сервере, лимиты длины, перечислимые значения, ограничение частоты (по умолчанию 5 заявок за 10 минут с IP), ключ идемпотентности против повторной отправки, отсев дублей за 10 минут, скрытое поле-ловушка, минимальное время заполнения, запрет запросов с чужих доменов, экранирование в письме.
- `From` — подтверждённый отправитель сервиса; email клиента ставится в `Reply-To`, только если это корректный адрес.
- Без JavaScript форма отправляется обычным POST, сервер отвечает страницей на языке заявки.
- В журнал сервера персональные данные не пишутся.

**Письмо о заявке.** Тема: «Новая заявка QADOQLAB — [вариант упаковки, отрасль или начало описания]». В теле: дата и время (Ташкент, UTC+5), язык сайта, компания, контактное лицо, контакт, город, что упаковать, вариант, задача, размеры и единицы, внутренние/внешние, количество, печать, страница-источник, вложения. IP, user-agent и технические идентификаторы в письмо не попадают.

## Развёртывание

Нужен хостинг с Node.js (VPS, Render, Railway, Fly.io и т. п.).

```
npm run build
npm start            # PORT, HOST, переменные почты — через окружение
```

За обратным прокси (nginx, Caddy, балансировщик) включите `TRUST_PROXY=true` (и `TRUST_PROXY_HOPS`, если прокси несколько), после подключения HTTPS — `HSTS=true`. Полный список мер защиты и чек-лист развёртывания — в [SECURITY.md](SECURITY.md).
Статический хостинг без сервера тоже покажет сайт, но онлайн-отправки не будет: форма останется в режиме письма.

Сервер отдаёт: CSP без `unsafe-inline` для скриптов (единственный встроенный скрипт разрешён по хешу), `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, сжатие brotli/gzip, `immutable`-кэш для файлов с хешем в имени, корректный 404.

## SEO

- Уникальные `title` и `description` для каждой страницы на обоих языках, Open Graph, `og:image` 1200×630.
- После указания `domain`: canonical, `hreflang` ru / uz / x-default, `sitemap.xml` (только опубликованные страницы), `robots.txt` с адресом sitemap.
- Пока домен пуст, все страницы `noindex`, `robots.txt` запрещает обход — тестовый адрес не попадёт в поиск.
- Структурированные данные: только `Organization` с названием, описанием, email и сайтом. Адреса, телефона, рейтингов и цен нет.
- Самарканд упоминается как приоритетная география, не как адрес. Отдельных страниц под города нет.

## Аналитика

Укажите `analytics.ga4Id` и/или `analytics.yandexMetrikaId` и пересоберите сайт — скрипт счётчика и разрешения в CSP добавятся автоматически.
События: `cta_click`, `form_open`, `form_start`, `form_submit_success` (только после подтверждения сервера), `form_submit_error`, `mailto_prepared`, `email_click`, `category_select`, `industry_select`, `language_switch`, `wizard_progress`.
Передаются только язык, страница, место кнопки, категория, отрасль, код ошибки. Имя, телефон, email, текст заявки и файлы в аналитику не уходят (белый список в `app.js`).

## Бренд и иллюстрации

- **Знак QADOQLAB — временный типографический знак**, не утверждённый логотип: квадратная «Q» с пунктиром линии сгиба клапана. Заменяется в `src/illustrations.js` (`MARK_PATHS`) и `src/static/favicon.svg`, затем `npm run render:static`.
- Все изображения коробок — **собственные векторные иллюстрации** (генерируются при сборке, 4–15 КБ каждая). На сайте они подписаны «Иллюстрация упаковки». Фотографий цеха, оборудования и людей нет.
- Шрифт — Manrope (кириллица и латиница, включая O‘ / G‘), один вариативный файл на набор символов, лицензия SIL OFL.
- Цвета — переменные в начале `styles.css`. Для мелкого текста медный цвет затемнён до `#8E5232`, чтобы контраст был не ниже 4.5:1; кромки полей — `#8C918A` (не ниже 3:1).

## Анимации и интерактив

Всё сделано на CSS, SMIL внутри SVG и собственном JS, без библиотек. Эффекты одноразовые: ничего не крутится постоянно, прокрутка не перехватывается.

**Первый экран**
- Строки заголовка выезжают из маски, под второй строкой прижимается полоска крафт-ленты.
- Коробки падают на подиумы с ускорением и дважды отскакивают.
- Открытая коробка приезжает закрытой и заклеенной: лента сматывается, раскрываются большие клапаны, за ними малые.
- На стоящих коробках лента протягивается по шву и прижимается сбоку. По иллюстрации один раз пробегает блик.
- Слои иллюстрации слегка следуют за мышью. При прокрутке иллюстрация немного отстаёт от страницы.
- На главной знак в шапке прорисовывается линией.

**Прокрутка**
- Блоки появляются по очереди, заголовки секций — по словам.
- Шапка уплотняется, показывает тонкую линию прогресса, прячется при прокрутке вниз и возвращается при прокрутке вверх.
- В «Как начать сотрудничество» медная линия заполняется по ходу прокрутки, точки вспыхивают, когда линия до них доходит.
- В финальном блоке развёртка коробки вырезается линией, затем проявляются сгибы. Пунктирный квадрат у блока сравнения поворачивается.
- Блок «Коробка под вашу продукцию»: развёртка вырезается, проявляются лист и сгибы, рядом опускается собранная коробка.
- В блоке сравнения галочки прорисовываются одна за другой. Крупный знак в подвале поднимается по буквам.

**Каталог**
- Коробка въезжает на подиум при появлении карточки.
- Карточка наклоняется в 3D за курсором, по верху растёт медная линия, за курсором — тёплое свечение.
- При переходе на страницу вида упаковки нажатая коробка перелетает в большую иллюстрацию (View Transitions; имя получает только нажатая карточка).

**Взаимодействие**
- Главные кнопки слегка тянутся к курсору. Подсветка под курсором, «волна» от нажатия.
- Стрелка на кнопках уезжает вправо и возвращается слева.
- Мобильное меню раскрывается кругом из кнопки. Плюс в FAQ поворотом превращается в минус, ответ раскрывается по высоте.
- В помощнике шаги сдвигаются в сторону перехода, у плиток линейные иконки, выбранная подпрыгивает. У отраслей тоже иконки.
- У полей при фокусе бежит медная линия. Ошибки выезжают, сводка ошибок «вздрагивает».
- При отправке по низу кнопки бежит полоса. Успех: коробка закрывается крышкой, заклеивается лентой, выскакивает значок с галочкой.
- Копирование адреса на странице контактов: два листа превращаются в галочку, результат озвучивается экранным читалкам.
- 404: заклеенная коробка приезжает и открывается — внутри пусто.
- Превью коробки рядом с полями размеров: изометрическая коробка плавно принимает пропорции введённых длины, ширины и высоты.
- Переход «Назад» между страницами идёт в обратную сторону. «О производстве» собирается так же, как первый экран.

**Ограничения**
- `prefers-reduced-motion`: движение отключается, картинки сразу в финальном состоянии.
- Без JavaScript всё видно сразу: скрытие до анимации включает только скрипт, у SVG статичные атрибуты хранят финальный кадр.
- Эффекты от прокрутки работают только там, где браузер поддерживает `animation-timeline`, в остальных браузерах всё статично.
- Наклон, магнит и отклик иллюстрации — только для мыши.
