# Безопасность

Что защищено, как это устроено и что нужно сделать при развёртывании. Каждый пункт из раздела «Что защищено» покрыт тестом в `scripts/test-server.js`, `scripts/test-admin.js` или `scripts/check.js`.

## Что защищено

### Публичный сайт

| Угроза | Защита |
|---|---|
| XSS через тексты, настройки, заявки | Все значения экранируются при сборке. JSON-LD экранирует `<`. В клиентском скрипте нет `innerHTML`: узлы строятся через DOM |
| XSS через DOM (Trusted Types) | Публичные страницы отдаются с `require-trusted-types-for 'script'; trusted-types 'none'`: браузер блокирует любую строку в `innerHTML` и в адресе скрипта. Режим отключается автоматически, если подключена аналитика: GA4 и Метрика сами вставляют скрипты |
| Внедрение скриптов | CSP без `unsafe-inline` и `unsafe-eval`; единственный встроенный скрипт разрешён по хешу. `base-uri 'none'`, `object-src 'none'`, `frame-src 'none'`, `worker-src 'none'` |
| Кликджекинг, чужие окна | `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin` |
| Подмена типа файла браузером | `X-Content-Type-Options: nosniff` на всех ответах |
| Обход каталогов, служебные файлы | Пути нормализуются и проверяются на выход за пределы сборки. Нулевые байты, `\`, файлы на `.` и `_` (например, `_build.json`) не отдаются |
| Открытое перенаправление | Путь `//host` не превращается в адрес другого сайта; перенаправление на каталог строится из проверенного пути |
| Падение сервера от кривого запроса | Любое исключение в обработчике → ответ 500 без подробностей. Неверная строка запроса → 400. Таймауты заголовков, тела и keep-alive; не больше 64 заголовков |

### Форма заявки

| Угроза | Защита |
|---|---|
| Спам и перебор | Лимит на IP (по умолчанию 5 за 10 минут), общий лимит на все заявки (60 за окно) для защиты квоты почты. Скрытое поле-ловушка и минимальное время заполнения |
| Двойная отправка | Ключ идемпотентности на каждую форму; одинаковая заявка в течение 10 минут не уходит второй раз |
| Подмена IP | `X-Forwarded-For` учитывается только при `TRUST_PROXY=true`. Берётся адрес, который записал ваш прокси (справа), а не то, что прислал клиент |
| CSRF | Запросы с чужим `Origin`, в том числе `null`, отклоняются |
| Вредоносные файлы | Тип проверяется по содержимому (JPEG, PNG, PDF), не по расширению. Не больше 3 файлов по 10 МБ. Файлы не сохраняются на диск, переименовываются в `attachment-N.ext` и уходят только во вложении письма |
| Внедрение в письмо | Тема очищается от переводов строк. Поля экранируются в HTML-версии. `From` — всегда подтверждённый отправитель сервиса; адрес клиента ставится только в `Reply-To` и только если он корректен |
| Загрязнение прототипа | Поля формы разбираются в объект без прототипа; `__proto__` и `constructor` ничего не меняют |
| Перерасход памяти | Все счётчики и кэши имеют потолок размера и срок жизни |
| Ложный успех | «Запрос отправлен» показывается только после ответа почтового сервиса |

### Админ-панель

| Угроза | Защита |
|---|---|
| Доступ без пароля | Без `ADMIN_PASSWORD_HASH` все адреса `/admin/` отвечают 404. Хеш в неверном формате тоже выключает панель |
| Утечка пароля | Хранится только хеш scrypt (N=32768, r=8, p=1, соль 16 байт). Сравнение — за постоянное время |
| Перебор пароля | 5 неудачных попыток за 15 минут с одного IP; 30 попыток со всех адресов вместе блокируют вход на 15 минут. Задержка 400 мс на каждую ошибку. Каждая попытка записывается в журнал |
| Кража и подделка сессии | Cookie `HttpOnly`, `SameSite=Strict`, `Path=/admin`, `Secure` при HTTPS. Срок жизни — 8 часов. Токен подписан HMAC-SHA256 вместе с хешем пароля, поэтому смена пароля завершает все сессии. Выход отзывает токен |
| CSRF | Изменения принимаются только со своего домена и только с заголовком `X-Admin-Request`, который нельзя отправить с другого сайта без CORS |
| Вредоносные данные в настройках | Каждое поле проверяется на сервере (`config/validate.js`): форматы, длины, перечисления. Тексты сохраняют подстановки `{email}`. Служебные ключи не редактируются. Сборка ещё раз проверяет `data/settings.json` и не запускается с неверными значениями |
| Вредоносные изображения | Тип и размеры определяются по заголовку файла (JPEG, PNG, WebP; до 6 МБ и 6000 px). Файл сохраняется под хешем содержимого |
| Поломка сайта при сохранении | Сайт собирается в отдельную папку и подменяет текущую только при успехе. Сборка ограничена 60 секундами. Данные пишутся атомарно (временный файл → переименование) |
| Индексация панели | `X-Robots-Tag: noindex`, `Disallow: /admin/` |
| Персональные данные | Панель не хранит заявки; в журнале нет имён, контактов и текста заявок |

## Чек-лист развёртывания

1. **HTTPS.** Поставьте сервер за nginx или Caddy с TLS. Включите `HSTS=true` и `TRUST_PROXY=true`; если прокси несколько, задайте `TRUST_PROXY_HOPS`.
2. **Прокси передаёт адрес клиента.** Для nginx: `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;` и `proxy_set_header X-Forwarded-Proto $scheme;`. Порт приложения не должен быть доступен из интернета напрямую.
3. **Секреты.** `RESEND_API_KEY`, `ADMIN_PASSWORD_HASH` и `ADMIN_SESSION_SECRET` хранятся только в переменных окружения или в `.env` с правами `600`. В git их нет (`.gitignore`).
4. **Пароль панели** — не короче 12 символов, уникальный. Создаётся командой `npm run admin:password`.
5. **Данные.** `DATA_DIR` — на постоянном диске, с резервной копией. Права — только у пользователя, от которого запущено приложение.
6. **Обновления.** Сайт работает без зависимостей, обновлять нужно только Node.js: используйте поддерживаемую LTS-версию.
7. **Журнал.** Сервер пишет в stdout вход в панель, неудачные попытки, сохранения и ошибки отправки — подключите сбор журнала на хостинге.

## Ограничения

- Счётчики попыток и сессии хранятся в памяти одного процесса. Для нескольких экземпляров за балансировщиком нужен общий `ADMIN_SESSION_SECRET` и привязка клиента к экземпляру (sticky sessions).
- Двухфакторной аутентификации в панели нет. Если нужен второй фактор, закройте `/admin/` на уровне прокси: ограничением по IP или Basic Auth поверх пароля панели.
